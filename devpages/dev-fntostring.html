Function.prototype.toString — does it still agree with .name?

Every function that claims to be native has to satisfy one formula, and it needs no reference browser to check: Function.prototype.toString.call(fn) === 'function ' + fn.name + '() { [native code] }'. Real built-ins satisfy it — accessors included, where .name is get width and the string is function get width() { [native code] }.

What this page was written for. _mn() masks by returning a Proxy, and in V8 a callable Proxy has no [[SourceText]], so Function.prototype.toString falls back to a generic function () { [native code] } — the name is gone. So every patched function in this extension failed the formula while every native one passed it, and the two could be told apart by a check that needs no list of what we patch. It hid from the rest of the suite because fn.toString() goes through the proxy's own trap and answers correctly; only the explicit Function.prototype.toString.call form exposed it.

The name loss is accepted, and that decision is measured. The only possible fix is replacing Function.prototype.toString globally — nothing done to a Proxy changes what it makes of one. That was written and withdrawn the same day, because CreepJS probes with Object.create(anyFunction).toString(): with a global replacement every function on the page, native ones included, starts resolving toString through us, and the shape of the thrown TypeError's stack is then checked. So this page does not fail on the name loss. It fails on the other thing the sweep finds — a function assigned bare, with no mask at all, whose toString prints real source. That is a fixable bug every time, and the first run of this page found three: _mnCtor's constructors, seven window setters in mw-adblock.js, and NetworkInformation.prototype.onchange.
