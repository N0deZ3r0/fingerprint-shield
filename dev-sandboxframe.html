Scriptless sandbox frames — protection coverage

Chrome logs "Blocked script execution in 'about:blank' because the document's frame is sandboxed and the 'allow-scripts' permission is not set" for every MAIN-world script it refuses to run in such a frame — and this extension's MAIN-world content script is declared all_frames + match_about_blank, so it is one of the things being refused. The message is therefore expected. The question that matters is whether the frame ends up UNPROTECTED, because a detector's whole point in creating one (SannySoft uses sandbox="allow-same-origin") is to read a canvas from a realm our scripts could not reach.

mw-canvas-audio.js claims to cover exactly this by patching such frames from the parent (_installFrameCanvasBridge / _isScriptlessSandbox). This page verifies that claim, and also demonstrates that a page can produce the same console message entirely on its own.
