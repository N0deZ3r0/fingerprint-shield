Audit

Runs in the extension's own page, which its content scripts do not patch — so this tab reads the host while the tab it inspects reads the profile, and the service worker supplies what was claimed. Three sources, in the browser you actually run. No rig can do this: branded Chrome refuses --load-extension, so every suite in test/ drives a browser this extension is never installed in.

Known limits — not checked above, and not closed

A green verdict means the tab reported the claim rather than the host on everything this page asks. These are the things it does not ask, because the answer is already known to be "visible". The reasoning for each is in README "Limits".

  • The machine is 2.6 bits. Six table profiles, so a site reading only the hardware sees one of six — or, with "This machine", exactly this machine, whose crowd is everyone with the same hardware. Country adds more, but the exit IP names it anyway.
  • Audio and text metrics are the host's. Text metrics are noised, audio is not — a two-machine diff measured audio as carrying nothing, and spoofing it would be one more invented value.
  • WebGL readback is noised, not controlled. We spoil our own rasterisation rather than claim someone else's.
  • The GPU is spoofed at the string level only. What actually runs on the card is still this card.
  • A site's own service worker reads the real machine. MV3 offers no way in; the only lever is the per-site allow/deny switch, which defaults to allow.
  • On a trusted-types or blob-refusing origin the machine is the host's — coherently. The worker cannot be patched there, so the window stops spoofing what a worker can see. The popup's "CSP → workers" switch rewrites that site's CSP instead, at the price of its nonce policy — per site, off by default.
  • The screen becomes the host's when the window is wider than the claim. At 150% zoom with a maximized window the resolution spoof does not apply.
  • A few media features disagree between @media and matchMedia — the row above counts them separately. Structural: matchMedia answers from the profile, the CSS engine from the real window.
  • The install window sends the host's user-agent. Free on Chrome, where the real and spoofed strings are identical; on Edge it carries Edg/.
  • A canvas read during document parse gets the default feature flags, not yours, on the first load of an origin.
  • Window geometry reads 0 before the browser knows it, exactly as in a clean browser — and no rig here can measure that axis.
  • The first visit to a site that refuses blob: workers costs it one worker. Every worker this extension patches is built from a blob, and a host is only known to refuse them once its headers have been seen — which is during that first load. Every visit after it, in any tab, is fine.
  • The decoder and the WebRTC codec list are the card's. HEVC support and video/H265 follow the host's hardware; only AV1's powerEfficient is downgraded for a claimed card without the decoder. "This machine" has no such gap.
  • The TLS and HTTP/2 handshake is not ours to touch. JA3/JA4 and the h2 SETTINGS fingerprint are decided at the socket, before any script runs, and no extension API reaches them — so that layer confirms or contradicts the claimed browser on its own.
  • The exit country is invisible to every check on this page. A perfectly coherent profile behind an IP in another country is a contradiction nothing here can see.
  • A WebGL warning about someone else’s enum names this extension. The page asks getParameter for a pname the context does not have, the driver refuses, and Chrome charges the console line to the innermost script frame — our wrapper. Same values and the same getError() as a clean browser; silencing it would cost the error flag, which a script CAN read.
  • Two marker names are fixed. '__t0' in window answers yes for us and no for a clean browser, in the top document and in frames, and __AFP_PATCH_URL is the worker’s equivalent. Non-enumerable, so a diff against a fresh iframe does not show them — but a name anyone can guess once needs no diff. Deriving them per site is blocked by the markers being set before the seed exists and by the in-browser checks that read them.
